## 1. 已知与所求

输入 n、目标和 target，以及 n 个整数，统计满足 i<j 且 a[i]+a[j]=target 的位置对数量。
0 ≤ n ≤ 2000，数值和 target 的绝对值不超过 10^9。输出一个整数。
注意，统计的是位置对；相同数值出现在不同位置，仍可能形成不同答案。

## 2. 第一反应：两个位置都试一遍

直接让两个下标都遍历全数组会遇到 `(i,i)`，还会同时遇到 `(i,j)` 与 `(j,i)`。
我们先规定表示方法：一个位置对只用“较小下标在前”的方式表示。
于是候选空间变成 `0 ≤ i < j < n`，代码里的第二层循环就从 i+1 开始。

这里要分清两件事：循环决定“检查谁”，if 决定“谁符合条件”。
不能把“这次样例能找到答案”当成完整性证明；应该解释任意一个合法答案如何进入循环。

## 3. 把上一课练习走完

数组 `[2,2,3,3]`，目标为 5：

| i | j 的取值 | 满足条件的位置对 |
|---|---|---|
| 0 | 1、2、3 | (0,2)、(0,3) |
| 1 | 2、3 | (1,2)、(1,3) |
| 2 | 3 | 无 |
| 3 | 无 | 无 |

答案为 4。不能先去重成 `[2,3]`，那会改变“位置对”的含义。

## 4. 为什么不漏、不重

任意两个不同位置总能唯一排成 i<j。外层必定走到 i，内层必定走到 j，所以不漏。
一个固定的有序下标组合只会被两层循环产生一次；反向组合因不满足 i<j 不会出现，所以不重。
if 又准确地检查和是否等于 target，所以被累计的恰好是所有合法答案。

## 5. 从运算次数到复杂度

内层总次数是 `(n-1)+(n-2)+...+1=n(n-1)/2`。
n=2000 时为 1999000 次；n=200000 时约为 200 亿次，这时需要改变方法。
用 O(n²) 描述其增长上界，常数 1/2 和低次项不影响数量级。本例也有紧确界 Θ(n²)。
复杂度不是“几秒钟”的保证：机器、编译器和每次操作的成本都会影响实际时间。

| 常见增长 | n 扩大 10 倍后的大致变化 | 常见来源 |
|---|---|---|
| O(log n) | 只增加少量步骤 | 每次缩小一半 |
| O(n) | 10 倍 | 单次遍历 |
| O(n log n) | 略大于 10 倍 | 比较排序 |
| O(n²) | 100 倍 | 两两枚举 |
| O(2^n) | 迅速爆炸 | 所有子集 |

本例保存输入占 O(n) 空间，除输入数组外只用 O(1) 额外空间。
计数使用 long long 是为后续更大规模版本保留余量。

## 完整 C++17 例题程序

独立源文件：[02-enumeration-complexity.cpp](../examples/02-enumeration-complexity.cpp)。输入输出约定见本章题目；程序针对题目保证的合法输入。

```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    long long target;
    if (!(cin >> n >> target)) return 0;
    vector<long long> a(n);
    for (auto &x : a) cin >> x;
    long long ans = 0;
    for (int i = 0; i < n; ++i) {
        for (int j = i + 1; j < n; ++j) {
            if (a[i] + a[j] == target) ++ans;
        }
    }
    cout << ans << '\n';
}
```

### 样例输入

```text
4 5
2 2 3 3
```

### 样例输出

```text
4
```

## 分层练习：先独立做，再展开答案

1. `[0,0,0,0]`、target=0 有多少对？为什么不是 16？
2. 统计三个不同位置的和，应该怎样限制 i、j、k？复杂度是什么？
3. n=200000 时，请只估计本章算法的检查次数，不运行大输入。说明为何需要新算法。

<details>
<summary>参考答案与思路（先尝试再看）</summary>

1. 6 对，即 C(4,2)=6。16 包括了自配对和交换位置后的重复。
2. 枚举 `i<j<k`，后两层分别从 i+1、j+1 开始。总组合数为 n(n-1)(n-2)/6，时间 O(n³)。
3. 19999900000 次，约 200 亿。瓶颈在候选对数量，换一种输入函数不能从根本上解决；第 07 章利用有序性减少检查。

</details>
