## 1. 将依赖关系画成图

有 n 个任务，编号 1 到 n，依赖 u→v 表示必须先完成 u 才能执行 v。
输入 n、m，随后 m 行 u、v；1≤n≤200000，0≤m≤200000，允许重边和自环。
输出一种合法执行顺序；如果存在环，输出 IMPOSSIBLE。
同一张图可能有多种合法顺序，本章不要求字典序最小。

顶点表示任务，边表示先后约束。注意方向：u→v 存在 u 的出边表中，同时给 v 增加入度。
入度就是“还有多少条来自前置任务的约束”。

## 2. 邻接表记录从一个点能走到哪里

`vector<vector<int>> graph(n+1)` 可以理解为 n+1 个列表，其中 graph[u] 保存 u 的全部后继。
编号从 1 开始，第 0 个列表不用。
相比 n×n 的邻接矩阵，邻接表在边较少时节省空间；本题用 O(n+m) 空间。
无向边通常要保存两个方向，本题是有向依赖，只保存 u→v 一次。

## 3. 每次选一个当前没有前置约束的任务

先把入度为 0 的任务全部入队。弹出 u，表示执行它；遍历其每条出边 u→v，把 v 的剩余入度减 1。
若 v 刚变为 0，就可以入队等待执行。
这不是按距离分层的 BFS，但同样使用队列管理“已经满足条件、尚未处理”的点。

## 4. 手算依赖图

四个任务，边为 1→3、2→3、3→4：

| 时刻 | 剩余入度 (1,2,3,4) | 队列 | 已输出 |
|---|---|---|---|
| 初始 | (0,0,2,1) | 1,2 | 空 |
| 完成 1 | (0,0,1,1) | 2 | 1 |
| 完成 2 | (0,0,0,1) | 3 | 1,2 |
| 完成 3 | (0,0,0,0) | 4 | 1,2,3 |

这里 3 必须等 1、2 都完成后才能进入队列，不能第一次被访问就执行。

## 5. 为什么能检测环

始终维护：尚未执行点的入度，等于来自尚未执行点的入边条数。
因此入度为 0 的点没有未完成的前置任务，输出它不会违反约束。
若仍有点没输出，但队列为空，则剩余每个点都有剩余前驱；不断沿前驱走，在有限个点中必然重复，形成环。
反过来，环上每个点都要等环内另一个点，谁都无法先变成入度 0，所以有环时不可能全部输出。

## 6. 边界与复杂度

每个点入队一次，每条边在起点被处理时扫描一次，时间和空间都是 O(n+m)。
重复边要相应重复计入度并重复扣除，保持一致即可；自环会使该点无法正常就绪。
若题目要求字典序最小，用小根堆替换队列，每次从所有就绪点中选编号最小者，代价变为 O(m+n log n)。

## 完整 C++17 例题程序

独立源文件：[12-graphs-toposort.cpp](../examples/12-graphs-toposort.cpp)。输入输出约定见本章题目；程序针对题目保证的合法输入。

```cpp
#include <iostream>
#include <queue>
#include <vector>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, m;
    if (!(cin >> n >> m)) return 0;
    vector<vector<int>> graph(n + 1);
    vector<int> indegree(n + 1, 0);
    for (int i = 0; i < m; ++i) {
        int u, v;
        cin >> u >> v;
        graph[u].push_back(v);
        ++indegree[v];
    }
    queue<int> ready;
    for (int u = 1; u <= n; ++u) {
        if (indegree[u] == 0) ready.push(u);
    }
    vector<int> order;
    while (!ready.empty()) {
        int u = ready.front();
        ready.pop();
        order.push_back(u);
        for (int v : graph[u]) {
            if (--indegree[v] == 0) ready.push(v);
        }
    }
    if (static_cast<int>(order.size()) != n) cout << "IMPOSSIBLE\n";
    else {
        for (int i = 0; i < n; ++i) {
            if (i) cout << ' ';
            cout << order[i];
        }
        cout << '\n';
    }
}
```

### 样例输入

```text
4 3
1 3
2 3
3 4
```

### 样例输出

```text
1 2 3 4
```

## 分层练习：先独立做，再展开答案

1. 1→2、2→1，再加一个孤立点 3，程序会输出合法顺序还是 IMPOSSIBLE？
2. 为什么不能只记录“一个任务是否曾被访问过”，代替入度？
3. 对某个输出顺序，设计一个不依赖拓扑排序实现的合法性检查方法。

<details>
<summary>参考答案与思路（先尝试再看）</summary>

1. IMPOSSIBLE。虽然 3 能执行，但 1、2 永远互相等待；局部能执行不等于全图无环。
2. 一个任务可能有多个前驱。被某一个前驱发现，只说明一条依赖已处理，不能代表全部依赖完成。
3. 检查 1..n 是否各出现一次；记录每个点的输出位置 pos；再逐边检查 pos[u]<pos[v]。所有边满足才是合法顺序。

</details>
