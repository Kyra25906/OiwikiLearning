# 第 04 章 · 排序与贪心：为什么先结束的活动值得先选

## 1. 先明确优化目标

有 n 场活动，每场占用半开时间区间 [l,r)，l<r。你一次只能参加一场，最多能参加多少场？
输入 n，随后 n 行 l、r；0≤n≤200000，端点绝对值不超过 10^9。输出最多场数。
半开区间意味着一场在 3 结束、下一场在 3 开始，可以衔接。
目标是“场数最多”，不是总时长最大，也没有活动权重。

## 2. 第一反应与反例

最早开始不一定好：`[0,10)、[1,2)、[2,3)`，先选 [0,10) 只能参加一场。
最短也不一定好：`[0,3)、[3,6)、[2,4)`，先选最短的 [2,4) 反而挡住另外两场。
直觉需要证明支持。我们改为每次选当前可参加活动中结束最早的，把后面尽可能多的时间留出来。

## 3. 排序把选择顺序固定下来

用 `struct Event { long long l, r; };` 把一场活动的开始和结束时间放在一起。
`sort(a.begin(), a.end(), 比较函数)` 对整个数组排序，范围是左闭右开。
比较函数返回 true 表示第一个参数应该排在第二个参数前面。
这里先比结束时间，再比开始时间；使用 `<` 而不是 `<=`，相等对象不能互相宣称“在前”。

代码中的 `[](const Event &a, const Event &b)` 是一个就地定义的小函数，叫 lambda。
`const` 表示不修改参数，`&` 表示不复制整条记录。先读懂它的输入和返回值即可。

## 4. 逐步选择

对 `[1,3)、[2,5)、[3,4)、[4,6)`，按结束时间排序后：

| 活动 | 是否选 | 最近结束时间 | 已选场数 |
|---|---|---:|---:|
| [1,3) | 选 | 3 | 1 |
| [3,4) | 选 | 4 | 2 |
| [2,5) | 不选，开始早于 4 | 4 | 2 |
| [4,6) | 选 | 6 | 3 |

排序只决定检查顺序；`l >= last` 才决定能否选择。

## 5. 为什么局部选择不会毁掉最优解

设 g 是结束最早的活动，某个最优方案的第一场是 o。因为 g.r≤o.r，把 o 换成 g 后，后续所有原来能接在 o 后面的活动仍能接在 g 后面。
因此存在一个以 g 开头、场数不变的最优方案。
选完 g 后，问题缩小为“在 g 结束之后继续安排”，重复同样论证，就得到整个贪心算法的正确性。
关键不是“每一步看着不错”，而是“可以把最优解改造成包含我的选择，且不变差”。

## 6. 复杂度与适用边界

排序 O(n log n)，扫描 O(n)，存储 O(n)。
用 has 标记是否已选择过活动，避免擅自把 last 初始化为 0，导致负时间活动被跳过。
若每场有不同价值，最早结束不再保证价值总和最大，需要重新建模，不能照搬本章结论。

## 完整 C++17 例题程序

独立源文件：[04-sorting-greedy.cpp](../examples/04-sorting-greedy.cpp)。输入输出约定见本章题目；程序针对题目保证的合法输入。

```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;
struct Event { long long l, r; };

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    if (!(cin >> n)) return 0;
    vector<Event> events(n);
    for (auto &e : events) cin >> e.l >> e.r;
    sort(events.begin(), events.end(), [](const Event &a, const Event &b) {
        if (a.r != b.r) return a.r < b.r;
        return a.l < b.l;
    });
    bool has = false;
    long long last = 0;
    int ans = 0;
    for (const auto &e : events) {
        if (!has || e.l >= last) {
            has = true;
            last = e.r;
            ++ans;
        }
    }
    cout << ans << '\n';
}
```

### 样例输入

```text
4
1 3
2 5
3 4
4 6
```

### 样例输出

```text
3
```

## 分层练习：先独立做，再展开答案

1. `[0,2)、[2,3)、[1,4)` 最多能选几场？
2. 如果改成闭区间 [l,r]，共享端点也算冲突，判断式怎么改？
3. 给三个活动加权，构造一个“最早结束”不能得到最大价值的反例。

<details>
<summary>参考答案与思路（先尝试再看）</summary>

1. 2 场，选前两场。端点 2 可以衔接。
2. 改为 `e.l > last`，题目对端点的定义会直接改变合法条件。
3. [0,1) 价值 1、[1,2) 价值 1、[0,2) 价值 100。按最早结束选前两场价值 2，而最优为最后一场价值 100。

</details>
